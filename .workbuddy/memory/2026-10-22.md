### 方案（已与用户确认）

## 装备加点等级上限：每词条自由投入 ≤ 人物等级

### 需求演进（用户怀疑 → 修正 → 定案）
1. 用户问：加点无上限要不要限制？提"第 100 关前最多 100、200 关前最多 200（百位粒度）"
2. 我分析：关卡↔等级是 ×10（第 k 关 = 等级段 (k-1)×10+1 ~ k×10），百位粒度会在

## 修复（二轮）：每日刷新只刷普通怪，BOSS 不回归

### 现象
一轮修复后用户反馈：怪物刷新了，但通关过的关 BOSS 没回来。

### 根因
一轮修复里 `bossDead` 一个字段承担了两个职责：
- 管解锁（"打过 BOSS"→ 开放下一关，**永久**，`maxStageFromProgress` 靠它）
- 管刷怪（`!prog.bossDead` 才刷 BOSS，**每日**）
保留 `bossDead` 就等于永远不刷 BOSS。

### 修法：职责拆分
`StageProgress` 加 `bossDay?: string`（BOSS 最近被击杀的日期，dayKeyOf 格式）：
- `spawnStageMonsters`：刷 BOSS 条件 `!prog.bossDead` → `prog.bossDay !== dayKeyOf(Date.now())`
- `recordKill(isBoss)`：置 `bossDay = 今天`（`bossDead` 照旧置 true 管解锁）
- `resetDailyStages`：清 `killed` 的同时清 `bossDay` → BOSS 跨天回归；`bossDead` 仍保留
- `normalizeState`：旧档无 `bossDay` → `undefined` → 非今天 → 下次铺怪 BOSS 直接回归
- 联动正确性：`onStageCleared`（BOSS 死后 900ms 重铺）时 `bossDay=今天` → 不重复刷 BOSS、普通怪满员

### 测试
146 全绿 + tsc 干净。新用例：BOSS 刷新看 bossDay 不看 bossDead、bossDay 存档往返、
旧档 bossDay 缺省。踩坑：`maxStageFromProgress` 连续推进才算解锁，测试断档设 bossDead 会得 1。

## 修复：每日 0 点怪物刷新完全没生效

### 现象
用户报告：设计是"每天凌晨 0 点刷新已解锁关卡中的所有 100 只怪物"，但第二天进游戏怪物还是昨天的残局。

### 根因
经典的"注释写了、代码没写"：`gameState.ts` 里 `StageProgress` 注释说"当天清零，次日刷新"，
但全代码库**没有任何按日期重置 `stages[k].killed` 的逻辑**。历史沿革：第六轮曾实现过
`stageDay` + 跨天重刷，第十轮"关卡大改"时被整体删除（旧日志有记录："删除 stageDay / dayKey
跨天刷新"），只留下 PLAN.md 两处互相矛盾的描述（§总表说有次日刷新、§3.9 说"取消次日刷新"）。

### 修法（状态与视觉分离）
1. `core/stage.ts` 新增：
   - `dayKeyOf(t)` → `'2026-10-22'` 格式的**本地时区**日期键（刷新按玩家本地 0 点，不用 UTC）；
   - `isSameLocalDay(a, b)`；
   - `resetDailyStages(s)` → 清空所有关卡 `killed`、**保留 `bossDead`**（通关是永久进度），
     返回是否真的清了东西（空进度不算刷新，不弹提示）。
2. `GameState` 加回 `stageDay: string`；`normalizeState` 兼容旧档（无该字段 → `''`
   → 首次读档自然触发一次刷新，把历史残局清掉）。
3. 场景 `checkDailyRollover()`（幂等，只改 state + 落盘，**不碰视觉**）：
   - `create()` 读档后调用（此时怪还没铺，后续 `spawnStageMonsters()` 自然铺出满员怪）；
   - `autoSave`（每 20s）里顺带检查 → **挂着游戏跨零点**也能刷，重铺 + toast；
   - `applyState()`（恢复备份/重置）开头调用（防恢复昨天的备份又把残局带回来）。
   - 跨零点重铺时顺手清 `attackTarget / moveTarget`（防悬空引用；`steerVelocity`
     本来会判 `sprite.active`，双保险）。
4. PLAN.md §3.9 里过时的"取消次日刷新"改为与实际行为一致。

### 踩坑
- 第一版 `checkDailyRollover` 在方法里直接 `clearMonsters + spawnStageMonsters`，
  但 `create()` 里调用点在 `monsterGroup` 创建**之前** → 会崩。教训：**状态与视觉分离**，
  场景构建期的刷新只改 state，铺怪留给既有的构建流程。
- `spawnMonster` 自带"离玩家 420px"落点保护，在线跨零点重铺不会把怪刷玩家脸上，无需额外处理。

  dayKeyOf 0 点翻转、旧档 stageDay=''、存读往返）/ `vite build` 未跑（本轮无构建相关改动）。
